## 1. 第一轮：先把一条样本走通

不要从所有依赖或长 Trainer 文件开始。先能说明“这一行 CSV 的哪个字段成为输入、哪个成为答案”。

| 顺序 | 文件与具体入口 | 阅读目标／自测问题 |
| --- | --- | --- |
| 1 | [训练 CSV](../data/Amazon/train/Industrial_and_Scientific_5_2016-10-2018-11.csv) 第一行、[SID 索引](../data/Amazon/index/Industrial_and_Scientific.index.json)、[商品元数据](../data/Amazon/index/Industrial_and_Scientific.item.json) | 找到商品 117、118。商品 ID、SID 码、词表 ID 有什么区别？ |
| 2 | [data.py](../data.py)：`Tokenizer`、`BaseDataset`、`CSVBaseDataset` | Dataset 是读取时编码还是初始化时编码？ |
| 3 | 同文件：`SidSFTDataset.get_history/pre` | 手画 input_ids、attention_mask、labels；为什么 prompt 的 label 是 -100？ |
| 4 | [sft.py](../sft.py)：`TokenExtender.get_new_tokens`、`train` | 为什么新增 token 后还要 resize？三个训练 Dataset 如何混合？ |
| 5 | [evaluate.py](../evaluate.py)：`main` 与嵌套 `evaluate` | 推理时目标在哪儿？为何只 decode `sequences[:,maxLen:]`？ |
| 6 | [LogitProcessor.py](../LogitProcessor.py)：`__call__` | 一个 SID 前缀如何决定下一 token 候选？ |
| 7 | [calc.py](../calc.py)：`gao` | 真实目标排第二时 HR@1、HR@3、NDCG@3 分别怎样算？ |

这一轮配合 02、03 第 4～5 节、04 的 SFT、05 阅读即可。读完应能口头串起：

```text
CSV 行 → SidSFTDataset.pre → HF Dataset → Trainer DataLoader/collator
→ model(**inputs) → causal LM loss → 参数更新
→ EvalSidDataset → model.generate → 前缀 mask → SID 列表 → 指标
```

其中 Trainer DataLoader、主 LLM forward 的内部实现属于外部库。找不到本仓库的对应类，不代表漏读了某个 `MiniOneRec` 模型文件。

## 3. 第三轮：理解推荐强化学习

按以下顺序读 [rl.py](../rl.py) 和 [minionerec_trainer.py](../minionerec_trainer.py)：

1. `rl.py::train` 的 Dataset 构造，回看 `data.py::SidDataset` 和 RL 辅助类。
2. `rule_reward`，先理解准确匹配为何能得到 0/1。
3. `ndcg_rule_reward`，用一组 `[错, 对, 错]` 手算 reward。
4. `RepeatRandomSampler.__iter__`，理解同一个 prompt 的 G 个候选如何成组。
5. `ReReTrainer.__init__` 的 policy/reference 与 generation 配置。
6. `_prepare_inputs`，先跟普通生成路径，再跟 reward、gather、advantage。
7. `_get_per_token_logps`，核对 C+1、去掉最后一位、取尾部 C 位的对齐关系。
8. `compute_loss`，理解 `exp(logp-logp.detach())` 为什么数值为 1 却有梯度。
9. 最后才读 dynamic sampling、add_gt、DAPO、GSPO 和训练中测试路径。

自测：同组全部 reward 为 0 时，advantage 为多少？这是否意味着整个 loss 永远没有梯度？答案是 advantage 为 0，但参考 KL 项仍可能有梯度。

还应能说出：本实现没有 value 网络、没有显式 old-policy ratio clipping；RL Shell 的 beam 分支保留采样，不能照搬独立评测的生成设定。

## 4. 第四轮：扩展与本地 Transformer 实现

想学习一个能在仓库里完整展开的注意力计算，先读 [sasrec.py](../sasrec.py) 的 `SASRec.forward`，再读 [SASRecModules_ori.py](../SASRecModules_ori.py) 的 `MultiHeadAttention.forward` 和 `PositionwiseFeedForward.forward`。对照 03 的 shape 表逐行走，注意 padding、因果 mask、合头、最后有效位置 gather。

然后读：

- TS-Rec：`ts_rec_sft.py::initialize_sid_token_with_text` → `ts_rec_data.py::SidTokenFeatDataset` → `train`。
- GPR：数据预处理增量 → `SidSFTDataset_GPR` → `VAFT_Trainer` → 真实 `train` 的类选择 → `rl_gpr.py::parse_sid/hepo_reward`。
- 测试：`data_test.py`、`tests/test_minimax_provider.py`，分清 Mock 与真实推理验证。

按这个顺序可以亲自发现“类已定义”和“入口已使用”之间的差别。06 列出的分支限制可作为核对清单，但不要用类名、注释或论文描述替代调用点。

## 5. 不运行大模型也能做的阅读练习

1. 取一条训练记录，在 `.index.json` 验证历史和目标的商品编号映射。
2. 手写两条不同长度 prompt 的左 padding 表，分别标出 input ID、attention mask、label。
3. 为两件共享前缀的商品画出允许 token 分支，解释为何随机拼三个合法 token 仍可能得到不存在的商品。
4. 用两个二维码本手算两层残差量化，比较重建向量与输入向量。
5. 手算一组奖励的均值、标准差和 advantage，观察全错组与部分命中组的区别。
6. 对照 `sft.sh` 和 `rl.sh`，算清 micro batch、候选数、不同 prompt 数与梯度累积的关系。

这些练习不会触发外部 API 或改变训练数据。若之后实际运行程序，先核对占位模型路径、脚本工作目录、SID 与 tokenizer 一致性；文档没有代替原代码修复这些条件。

## 6. 读完后应能回答的八个问题

| 问题 | 对应事实 |
| --- | --- |
| 用户 ID 是否进入默认 LLM？ | 不进入；默认用历史 SID prompt 表达条件 |
| SID 是一个商品编号还是多个 token？ | 完整商品代码由多个层 token 拼接，当前附带数据为三层 |
| 主模型在哪定义？ | `AutoModelForCausalLM` 从外部 checkpoint 加载 |
| SFT label 是什么？ | 答案 token ID，prompt 和 padding 对应 -100 |
| 为什么训练输入中有答案？ | teacher forcing 与因果位置移位，不是推理输入目标 |
| RQ-VAE 与 LLM 一起反传吗？ | 默认不一起；SID 文件连接独立阶段 |
| 推理如何避免任意编造商品？ | 目录前缀约束；不匹配时存在 EOS 回退，仍需核对有效性 |
| 候选 SID 能唯一还原商品吗？ | 不保证；附带索引有碰撞，主线未实现业务消歧 |

如果这八个问题能结合具体函数回答，就已经掌握项目主线。进一步学习应围绕一个明确实验问题展开，例如替换 SID 构建方式如何影响碰撞率和推荐指标，而不是一次打开所有可选分支。
