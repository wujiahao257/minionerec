# 09 目录迁移与遗留代码检查

[返回文档目录](README.md)

> 本篇记录此前的目录迁移。后续按学习主线的要求，已删除传统推荐基线及其 RL 奖励入口，见 [11 主线精简记录](11_主线精简记录.md)。

## 1. 本次整理了什么

主代码移入 `minionerec/` 包，按职责拆目录，保留现有类、函数和算法实现。根目录不再放 Python 文件和 Shell 文件。数据文件仍在 `data/` 与 `ts_rec_data/`，没有移动训练数据、模型权重或删除实验代码。

没有使用根目录的 `datasets/` 作为代码包，以免遮蔽 Hugging Face 的 `datasets`。主线使用绝对包导入，例如 `from minionerec.datasets.recommendation import SidSFTDataset`。`__init__.py` 只声明包，不会因导入包就加载模型。

`rq/` 是独立的量化子项目，内部仍保留本地 `datasets`、`models`、`utils` 导入及原来的启动习惯；本次没有把它强行改造成与主线共用的模块。

## 2. 整理后的运行方式

以下命令以项目根目录为当前目录，并假定原有依赖已安装、模型及数据路径已填写。

```bash
# 使用现成样例；先配置脚本中的模型、数据和输出路径
bash scripts/sft.sh
bash scripts/rl.sh
bash scripts/evaluate.sh
bash scripts/ts_rec_sft.sh

# 自行传参时，使用模块入口
python -m minionerec.preprocessing.convert_dataset --help
python -m minionerec.training.sft --help
python -m minionerec.training.rl --help
python -m minionerec.evaluation.evaluate --help

# 分布式入口也必须使用模块参数
torchrun --nproc_per_node 8 -m minionerec.training.sft --base_model /path/to/model
accelerate launch --config_file config/zero2_opt.yaml -m minionerec.training.rl --model_path /path/to/model

# RQ 的 Shell 样例集中在 rq/scripts，并自行切换到所需工作目录
bash rq/scripts/amazon_text2emb.sh
bash rq/scripts/rqvae.sh
python -m rq.vae.generate_indices --ckpt_path /path/to/best_collision_model.pth
```

`scripts/` 中的脚本会自动进入项目根目录，所以相对参数路径也以根目录为准。除多命令调度的 `evaluate.sh` 外，脚本会把额外参数 `"$@"` 转发给 Python；同名参数在末尾可以覆盖样例默认值。评测的 `exp_name` 在脚本内配置，不提供虚假的 `--exp_name` 选项。

Amazon18 清洗样例显式传入原始元数据和评论路径，不再隐含依赖从 `data/` 启动。更换领域时同时指定 `--dataset`、`--metadata_file` 和 `--reviews_file`。

TS 样例原本错误地调用普通 SFT，却传入它不接受的 `description_path`；现已调用 TS 专用入口，并将描述文件路径改为仓库提供的 `ts_rec_data/${category}.description_keywords.json`。

旧的 `python sft.py`、`from data import …` 等入口已迁移，不保留根目录兼容副本。若外部脚本有旧命令或导入，请按下面的表更新。现有保存的 `state_dict` 和 Transformers checkpoint 格式没有改变；外部用 pickle 保存完整 Python 类对象的产物可能依赖旧模块路径，本次没有为这类未在主保存流程中使用的格式增加兼容层。

## 3. 有没有明确标记为过时的代码

检查范围：受 Git 跟踪的 Python、Shell、Markdown 文件；检索 `deprecated`、`obsolete`、`legacy`、`deprecat`、`过时`、`弃用`、`旧版`，并检查调用方和实现。另对照原始提交 `5f4f733`，排除后来添加的中文注释造成的误判。

**未发现原作者明确宣布某个模块弃用的标记。** 上一轮中文注释里出现的“旧版”是基于实现的说明，不是原作者的弃用声明。因此没有按关键词批量删除代码，实验分支也不能直接等同于过时代码。

## 5. 验证方法与边界

目录结构测试检查本地导入、脚本模块入口、Python 语法、文档链接和旧入口残留。迁移检查还会比较新旧文件的语法树，除本地导入及测试路径外应保持相同。

```bash
python -m unittest tests.test_repository_layout -v
# 安装项目依赖后，可继续执行原有 Dataset 测试
python -m unittest tests.test_datasets -v
```

本次结果：6 项结构测试通过；23 个迁移 Python 文件除预期的本地导入和测试路径调整外，语法树相同；7 个迁移 Shell 脚本通过 `bash -n`。另将训练命令替换为测试桩，从项目外目录启动 6 个单入口脚本，确认工作目录定位和参数转发正确，没有执行真实训练。

结构验证不能代替 GPU 训练或 checkpoint 数值回归。本次环境缺少 torch、pandas、transformers 等训练依赖，不宣称已经跑通 SFT、RL 或真实模型推理。
