# 02 数据、训练样本与标签

## 1. 先区分四种“ID”

| 名称 | 示例 | 谁使用它 |
| --- | --- | --- |
| 原始商品标识 | Amazon ASIN / parent_asin | 原始评论和元数据关联 |
| 重编号商品 ID | `118` | `.item.json`、`.index.json` 的键与 CSV `item_id` |
| Semantic ID 字符串 | `<a_104><b_118><c_176>` | prompt、推荐目标、评测字符串 |
| tokenizer token ID | 某三个整数，实际值由 tokenizer 决定 | LLM 的 `input_ids` 和 `labels` |

`<b_118>` 中的 `118` 是码本编号，并不是商品 `118`。量化器码本索引与语言模型词表索引也不是同一个整数空间。`minionerec/training/sft.py::TokenExtender` 收集 token 字符串，再由 tokenizer 分配词表编号。

## 2. 从原始记录构造历史窗口

依据：[minionerec/preprocessing/amazon18.py](../minionerec/preprocessing/amazon18.py)。实际执行顺序为：

```text
__main__ / parse_args
→ load_reviews_json2csv_style
→ process_dataset_recursive
   → load_metadata_json2csv_style
   → k_core_filtering_json2csv_style
→ convert_inters2dict_amazon18_style
→ generate_interaction_list_json2csv_style
→ convert_to_atomic_files_json2csv_style
→ create_item_features_amazon18_style / load_review_data_amazon18_style
→ 写 JSON 和重编号映射
```

### 清洗与 K-core

元数据处理保留合法标题：标题长度大于 1、按空格分词不超过 20 个词，并排除特定 HTML 异常标题。K-core 循环按时间区间过滤，反复移除交互数小于 K 的用户和商品。

为什么循环？移除低频商品后，有些用户的剩余交互可能不足 K；再移除这些用户，又可能使别的商品不足 K。代码持续到不再发现需要移除的对象。

当前 Amazon18 入口给过滤函数传入的是 `args.user_k`，它同时作为用户和商品阈值。虽然参数中定义了 `item_k`，这里没有单独使用它。时间上界是指定结束月份的第一天零点，不能把它读成该月最后一天。商品不足 3,000 时，`process_dataset_recursive` 会尝试把起始年份向前移，最早到 1996。

### 排序和滑窗

`convert_inters2dict_amazon18_style` 为用户和商品建立从 0 开始的连续编号；按用户收集、按时间排序，保留重复交互。`generate_interaction_list_json2csv_style` 对每个用户的第 `i` 条行为，取：

```python
st = max(i - 10, 0)
history = items[st:i]
target = items[i]
```

教学示例，用户顺序为 `A → B → C → D` 时：

| 历史 | label 所指的商品 |
| --- | --- |
| `[A]` | B |
| `[A, B]` | C |
| `[A, B, C]` | D |

第一个交互不产生预测样本，因为它之前没有历史。窗口最多 10 个商品。后面写 `.inter` 时虽又取 `[-50:]`，但不会把已有的 10 条变成 50 条。

### 划分不是每个用户的留一法

所有用户的窗口先合并，再按**目标交互时间**全局排序，前 80% 训练、中间 10% 验证、最后 10% 测试。它不是对每个用户单独“最后一条测试、倒数第二条验证”，也不是随机划分。

测试窗口可包含在测试时刻之前已经发生的验证／测试时期行为；这是按时间滚动构造历史的结果，不是把目标行为提前放进该条样本的历史。

`.inter` 的格式是制表符分隔：

```text
user_id:token    item_id_list:token_seq    item_id:token
22              117                      118
```

这个例子展示格式，不声称附带原始 `.inter` 文件就在仓库中；当前提交附带的是转换后的 CSV。

Amazon23 的入口 [minionerec/preprocessing/amazon23.py](../minionerec/preprocessing/amazon23.py) 使用 `parent_asin`、`user_id`、`timestamp`，把毫秒时间转成秒，再按同样的 10 条历史和全局时间划分产出文件。它不包含 Amazon18 的递归扩展年份步骤。

## 3. 商品文本变向量，再变 SID

[rq/text2emb/amazon_text2emb.py](../rq/text2emb/amazon_text2emb.py) 的顺序：

1. `preprocess_text → load_data → generate_text`：读取 `.item.json`，选 `title` 和 `description` 清洗、拼接。
2. `load_qwen_model`：通过 `AutoTokenizer`、`AutoModel` 加载用户指定 checkpoint。
3. `generate_item_embedding`：按进程划分商品，每批 tokenizer 编码，模型输出 `last_hidden_state`，对非 padding token 做平均。
4. 汇总 `(商品编号, 向量)`，按编号排序后保存 `[商品数, 文本隐藏维度]` 的 `.npy`。

这条链在 `model.eval()`、`torch.no_grad()` 下运行，没有优化器。文本清洗实际来自 `rq/text2emb/utils.py::clean_text`，会处理 HTML、引号与换行，并把长度达到 2,000 字符的清洗结果置空；不能只把它理解为无损拼接。

后续量化训练见 [03 模型架构](03_模型架构.md)。对于 RQ-VAE，导出器按向量数组行号写商品索引。因此编号连续、向量行序、`.item.json` 键与 SID 键必须保持一致。换了一份元数据排序，不能随便沿用旧 SID。

## 4. 转换为主训练 CSV

依据：[minionerec/preprocessing/convert_dataset.py](../minionerec/preprocessing/convert_dataset.py) 的 `main → load_dataset → create_item_info_file → convert_interactions_to_csv`。

| CSV 字段 | 内容 | 默认 SID 推荐是否直接输入它 |
| --- | --- | --- |
| `user_id` | `A` 加重编号用户 ID | 否 |
| `history_item_title` | Python 列表的字符串表示 | 主 SID 任务否；标题任务使用 |
| `item_title` | 目标标题 | 标题监督任务使用 |
| `history_item_id` | 历史整数 ID 列表的字符串表示 | 主 SID prompt 不直接使用 |
| `item_id` | 目标整数 ID | 元数据关联等 |
| `history_item_sid` | 历史 SID 列表的字符串表示 | 是 |
| `item_sid` | 目标 SID 字符串 | 用来构造答案 |

`semantic_tokens_to_id` 使用 `''.join(tokens)`，保留尖括号且不加空格。`.info` 文件每行是 `SID<TAB>标题<TAB>商品ID`，为解码提供允许生成的商品目录。

几个影响样本的真实行为：

- 目标没有 SID 时，整条样本跳过；历史缺少 SID 时只跳过相应历史 SID。标题也独立按是否有元数据过滤，未做三种历史列表长度一致性断言。
- `convert_interactions_to_csv` 函数签名的 `keep_longest_only=True`，但 CLI 参数默认 `False`，`main` 显式把 CLI 值传进去。直接运行脚本默认保留所有训练窗口。
- 若打开最长窗口模式，只在长度**严格更大**时替换旧样本。多个长度 10 的窗口会保留先遇到的一个，不保证是最新行为。
- 输出 CSV 文件名中的 `2016-10-2018-11` 是固定字符串，不是从原始时间边界自动推导出来的。

## 5. 仓库附带数据的实测结构

下表通过读取当前文件得到；`.npy` 的 shape 和 dtype 从文件头检查。

| 数据集 | 商品数 | 不同完整 SID 数 | train / valid / test 行数 | 向量 shape / dtype |
| --- | --- | --- | --- | --- |
| Industrial_and_Scientific | 3,686 | 3,670 | 36,259 / 4,532 / 4,533 | `[3686,2560]` / float16 |
| Office_Products | 3,459 | 3,444 | 38,924 / 4,866 / 4,866 | `[3459,2560]` / float16 |

两套索引的每个商品都有三个 SID token。全部 CSV 的历史长度为 1～10；逐行核对历史和目标与 `.index.json` 的对应关系，没有发现不一致。两份 info 分别有 3,686 和 3,459 行，其 SID 与对应商品索引一致。

不同 SID 数少于商品数意味着存在碰撞。不能把“数据映射一致”误解为“SID 唯一”。辅助 Dataset 用字典做 SID↔标题映射时，相同键还可能被后来的条目覆盖。

## 6. 一条真实样本怎样变成模型输入

依据：[minionerec/datasets/recommendation.py](../minionerec/datasets/recommendation.py) 的 `CSVBaseDataset.__init__`、`BaseDataset.get_inputs/__getitem__`、`SidSFTDataset.get_history/pre`。

构造 Dataset 时先 `pd.read_csv`，再立即对所有行调用 `pre`，存进 `self.inputs`。所以 `__getitem__` 只是取已经构造好的字典，并不是每次取样都重新随机编 prompt。

Industrial 第一条训练记录的关键字段：

```text
user_id = A22
history_item_id = [117]
item_id = 118
history_item_sid = ['<a_165><b_107><c_44>']
item_sid = <a_104><b_118><c_176>
```

`SidSFTDataset.pre` 把它变成下列结构（省略模板中的部分空白）：

```text
Below is an instruction ...

### Instruction:
Can you predict the next possible item that the user may expect?

### User Input:
The user has interacted with items <a_165><b_107><c_44> in chronological order.
Can you predict the next possible item that the user may expect?

### Response:
<a_104><b_118><c_176>\n
```

代码先保存答案，再把 `history['output']` 清空去构造 prompt。随后独立编码答案并追加 EOS。这样 `### Response:` 后的答案只在监督训练的 token 序列尾部出现。

设 prompt 编码为 `p₀...pₘ₋₁`，答案编码为 `a₀...aₙ₋₁`，其中包含换行及 EOS 的实际编码：

```text
input_ids      = [p₀, ..., pₘ₋₁, a₀, ..., aₙ₋₁]
attention_mask = [ 1, ...,     1,  1, ...,     1]
labels         = [-100, ...,-100, a₀, ..., aₙ₋₁]
```

label 不是评分，不是 0/1，也不是单个商品整数，而是答案各位置的 **token ID**。`-100` 表示这些位置不作为 loss 的监督目标；它不是词表 token，不会送进 Embedding 查表。

为什么 prompt 要参与 forward 但不计算其输出 loss？它提供用户历史与任务条件。我们希望模型根据条件答对，而不是把主要优化目标放在背诵固定指令上。`attention_mask=1` 和 `labels=-100` 可以出现在同一位置：前者允许模型使用上下文，后者只控制监督。

`Tokenizer.encode` 清理编码结果开头的 BOS、末尾的 EOS，再按参数补充。`pre` 的训练返回值都取 `[-max_len:]`，即保留尾部；答案通常能留下，但超长情况下开头指令和较早历史会被截断。`test=True` 在截断代码之前返回，当前评测 Dataset 因而没有实际应用 `max_len` 截断。

## 7. 多任务 label 分别是什么

`minionerec/training/sft.py` 当前启用：

| Dataset | prompt 内容 | 答案／label |
| --- | --- | --- |
| `SidSFTDataset` | 历史 SID | 下一个 SID + 换行 + EOS |
| `SidItemFeatDataset` | “这个 SID 的标题是什么？” | 标题 + 换行 + EOS |
| `SidItemFeatDataset` | “这个标题对应哪个商品？” | SID + 换行 + EOS |
| `FusionSeqRecDataset` | 历史 SID | 下一个商品标题 + 换行 + EOS |

这些任务共享一个 tokenizer、一个模型和同一种语言模型 loss。辅助任务建立文本与代码的联系；没有单独的对比学习 head，也没有给这三个 Dataset 配独立 loss 系数，混合比例主要由样本数决定。

`SidItemFeatDataset` 和 `FusionSeqRecDataset` 都只拼 `sids[0]+sids[1]+sids[2]`。若改用带第四层消歧码的索引，CSV 的完整 SID 与这里的三层键可能不同。Fusion 查询不到时会回退到目标 SID 字符串，不能假设这种情况下仍在正确监督标题。

## 8. RL 和评测如何不同

RL 的 `SidDataset.pre` 返回字符串 `{'prompt': ..., 'completion': ...}`，不返回 SFT 的 `labels`。它还建立 `prompt2history`、`history2target`，奖励函数从中查正确答案。其 prompt 不加 SFT 的长 instruction 前缀。

RL 默认入口另外创建 `RLTitle2SidDataset`（标题或描述 → SID）和 `RLSeqTitle2SidDataset`（历史标题 → SID）；后者固定请求随机抽样 10,000 行。CSV 基类直接调用 `DataFrame.sample(n=sample)`，训练集不足 10,000 行时不会自动缩小，会报错。

`EvalSidDataset(test=True)` 只返回 prompt 的 token 与 mask，目标保留在 `get_all()` 的结果里用于之后对比。它的历史问句与 SFT 不完全相同。这是当前代码事实，不应在讲解中把三个阶段的模板写成完全一致。

SFT 的答案用于 teacher forcing；RL 的模型自己生成答案后获得 reward；评测的真实答案不参与生成。三者读取相似字段，但监督方式不同。
