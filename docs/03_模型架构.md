# 03 模型架构、Embedding 与 Tensor shape

[返回目录](README.md) · [上一篇](02_数据处理.md) · [下一篇：训练流程](04_训练流程.md)

## 1. 全文符号

| 符号 | 含义 |
| --- | --- |
| B | 一批样本数，具体章节会注明是商品数还是序列数 |
| N | 商品总数 |
| T | 文本编码序列长度 |
| D | 商品文本模型隐藏维度，附带 `.npy` 为 2560 |
| d | RQ 量化空间维度；`rq/rqvae.py` 默认 32 |
| M | 量化层数；RQ-VAE 入口默认 3 |
| Kₗ | 第 l 层码本向量数量；默认每层 256 |
| L | 推荐 LLM 的总 token 长度，含文本模板和答案 |
| H / V | 推荐 LLM 隐藏维度／扩充后的词表大小，由 checkpoint 与 tokenizer 决定 |

`D`、`d`、`H` 不是同一个参数。SID 是连接两个阶段的离散文件表示，不要求三个维度相等。

## 2. 商品文本编码器：把一句话压成一个向量

源码：[rq/text2emb/amazon_text2emb.py](../rq/text2emb/amazon_text2emb.py)，`generate_item_embedding`。

| 操作 | 输入 shape | 输出 shape |
| --- | --- | --- |
| tokenizer，右 padding | B 条标题描述字符串 | `input_ids`、`attention_mask`：`[B,T]` |
| `AutoModel(...)` | `[B,T]` | `last_hidden_state`：`[B,T,D]` |
| `mask.unsqueeze(-1).expand(...)` | `[B,T]` | `[B,T,D]` |
| 隐状态乘 mask 后沿 token 维求和 | `[B,T,D]` | `[B,D]` |
| 除以有效 token 数 | `[B,D]` | 商品向量 `[B,D]` |
| 各批拼接、按商品 ID 排序 | 多个 `[B,D]` | `.npy`：`[N,D]` |

对于第 i 件商品，计算的含义是：

```text
xᵢ = Σₜ(maskᵢₜ × hiddenᵢₜ) / max(Σₜ maskᵢₜ, 1e-9)
```

padding 是为凑成矩形 Tensor 人工补上的，不应该影响商品内容，所以要用 mask 排除。这里是 masked mean pooling，不是取最后一个 token，不是 `[CLS]` 池化，也没有在保存前额外做 L2 单位化。

文本模型内部 Transformer 来自外部 `AutoModel`。本仓库只使用它的输出接口，没有定义它的内部 block。

## 3. RQ-VAE：学一个可重建的离散表示

调用关系：

```text
rq/rqvae.py
→ EmbDataset → DataLoader
→ rq/trainer.py::Trainer._train_epoch
→ RQVAE.forward
   → MLPLayers.forward（encoder）
   → ResidualVectorQuantizer.forward
      → VectorQuantizer.forward，重复 M 层
   → MLPLayers.forward（decoder）
→ RQVAE.compute_loss
```

### 3.1 编码器与解码器

[rq/models/rqvae.py](../rq/models/rqvae.py) 的 `RQVAE.__init__` 构造：

```text
encoder dimensions = [in_dim] + layers + [e_dim]
decoder dimensions = encoder dimensions 的逆序
```

按 `rq/rqvae.py` 默认参数和附带向量的维度：

```text
x: [B,2560]
→ [B,2048] → [B,1024] → [B,512]
→ [B,256] → [B,128] → [B,64] → z: [B,32]
→ 残差量化 z_q: [B,32]
→ [B,64] → [B,128] → [B,256]
→ [B,512] → [B,1024] → [B,2048] → out: [B,2560]
```

这是按入口默认值推导的 shape，不是在声称附带 SID 必然由这些参数训练得到；仓库未附相应 checkpoint 来证明其训练配置。

[rq/models/layers.py](../rq/models/layers.py) 的 `MLPLayers` 每层为 Dropout、Linear，中间层可加 BatchNorm，并使用 ReLU；末层不加激活。默认 `dropout_prob=0`、`bn=False`。编码器把文本表示压入量化空间；解码器让训练能检验离散代码是否保留了原向量信息。

名称虽叫 RQVAE，这里的 `RQVAE` 没有均值／方差预测、随机重参数采样或高斯先验 KL loss。不要把普通变分自编码器的这些结构补进本实现。

### 3.2 单层 VectorQuantizer

源码：[rq/models/vq.py](../rq/models/vq.py)，`VectorQuantizer.forward`。

码本 `embedding.weight` 是 `[Kₗ,d]`，可理解为 Kₗ 个可学习“代表向量”。对当前残差 `r:[B,d]`，代码计算它到每个代表向量的平方距离：

```text
||r||²                      [B,1]
+ ||codebook||²             [1,Kₗ]
- 2 × r @ codebook.T        [B,Kₗ]
= distances                [B,Kₗ]
```

普通路径用 `argmin(dim=-1)` 得 `indices:[B]`；Embedding 查表得到 `x_q:[B,d]`。选择最近代表向量，相当于把连续位置映射成一个整数代码。

当 `use_sk=True` 且 `sk_epsilon>0` 时，会中心化距离，调用 `sinkhorn_algorithm` 得 `[B,Kₗ]` 的分配矩阵，再 `argmax`。它通过反复归一化鼓励分配平衡；最后仍是离散取最大，不应把它描述成严格保证每个码使用次数相等。默认训练参数的三个 epsilon 都是 0，实际走最近邻路径。

若 `kmeans_init=True`，首个训练 forward 会从当前输入 latent 做 KMeans 初始化码本，而不是预先遍历全部商品再初始化。

### 3.3 为什么要残差量化

源码：[rq/models/rq.py](../rq/models/rq.py)，`ResidualVectorQuantizer.forward`：

```text
residual₀ = z                        [B,d]
q₀ = 第 0 层选出的向量                [B,d]
residual₁ = residual₀ - q₀           [B,d]
q₁ = 第 1 层对 residual₁ 的量化        [B,d]
residual₂ = residual₁ - q₁           [B,d]
q₂ = 第 2 层对 residual₂ 的量化        [B,d]
z_q = q₀ + q₁ + q₂                  [B,d]
indices = stack([i₀,i₁,i₂], -1)      [B,3]
```

第一层先表达一部分信息，后面层再表达剩余误差。这样 M 个小码本可以组合出很多路径，而不用为每个商品单独存一个巨大类别表。层次只表达残差分解顺序，不自动对应人工类目。

`RQVAE.forward` 返回三个对象：重建 `out:[B,D]`、量化平均 loss 标量、索引 `[B,M]`。`get_indices` 只走 encoder 和 RQ，不走 decoder，因为导出 SID 不需要重建向量。

### 3.4 梯度如何穿过离散选择

`argmin` 的整数结果不能像 Linear 一样连续求导。代码使用：

```python
x_q = x + (x_q - x).detach()
```

前向数值仍是查表后的量化向量；反向对当前输入的导数按恒等映射处理，这叫直通估计。码本自身由单独的 codebook loss 学习。具体重建与量化 loss 在 [04](04_训练流程.md) 中展开。

还有一个阅读高级细节：当前代码用直通结果直接做 `residual = residual - x_res`。按这条计算图，不能简单声称“每一层量化损失都以相同方式回传到原始 encoder”；需要尊重每层 detach 和残差减法产生的梯度路径。

## 4. SID 文件怎样进入语言模型

[rq/generate_indices.py](../rq/generate_indices.py) 把 `[a,b,c]` 整数索引格式化成 `['<a_a>','<b_b>','<c_c>']`（此处字母只是占位符），按商品行号写 JSON。

[minionerec/training/sft.py](../minionerec/training/sft.py) 的 `TokenExtender.get_new_tokens` 汇总所有层 token、去重并排序，然后：

```python
tokenizer.add_tokens(new_tokens)
model.resize_token_embeddings(len(tokenizer))
```

为何必须 resize？如果 tokenizer 给新 token 分配了超出旧词表的编号，旧的 Embedding 没有对应行；输出词表也需要能预测新 token。实际输入／输出权重如何共享及初始化，由所加载模型的实现决定。

这里添加的是普通新增 token，不是 `add_special_tokens`。因此 SID 不应像 EOS 那样在 `skip_special_tokens=True` 时被删除。

**三类 Embedding 不要混淆：**

| 所属模块 | shape | 作用 |
| --- | --- | --- |
| 商品文本模型的词表 Embedding | 由文本模型决定 | 把标题和描述 token 编成向量 |
| RQ 码本 Embedding | 每层 `[Kₗ,d]` | 把量化索引映射到代表向量 |
| 推荐 LLM 的词表 Embedding | `[V,H]` | 把自然语言和 SID token ID 映射为推荐上下文表示 |

主线没有把 RQ 码本的 `[Kₗ,d]` 权重复制到 LLM 的 `[V,H]` 中。两个阶段通过 SID 字符串衔接。TS-Rec 额外用关键词初始化 LLM 行，见 06；它也不是复制 RQ 码本。

## 5. 主推荐 LLM 的 forward

主模型入口是 `minionerec/training/sft.py::train` 的 `AutoModelForCausalLM`。仓库没有固定它必须是哪一款 Qwen，也没有附可核验的主模型配置文件。下面区分**可确认的输入输出契约**和**用于理解的 Transformer 概念**。

### 可从调用端确定的 shape

| 步骤 | shape | 含义 |
| --- | --- | --- |
| 单条 Dataset 样本 | 三个长度为 `Lᵢ` 的列表 | prompt 加答案；label 的 prompt 段为 -100 |
| collator 左侧补齐 | `[B,L]` | L 为批内最大长度向上补齐到 8 的倍数 |
| `input_ids` / `attention_mask` / `labels` | `[B,L]` | ID、有效上下文、监督目标 |
| 词表 Embedding | `[B,L,H]` | 每个 token 一条 H 维向量 |
| 因果语言模型隐藏状态 | `[B,L,H]` | 各位置根据允许的前缀形成表示 |
| 词表预测 logits | `[B,L,V]` | 各位置预测下一个 token 的未归一化分数 |
| 因果位置对齐后的监督 | `[B,L-1,V]` 对 `[B,L-1]` | 前一个位置预测后一个 token |
| 模型返回的 `loss` | 标量 | 主 SFT 交给外部模型计算 |

batch 中有多少历史商品，不等于 token 长度 L。三个 SID token 之外还有模板、逗号、空格、换行，标题辅助任务的答案也可能很长。

### Transformer 为什么能读历史

从概念上，因果自注意力让当前位置对前面的 token 分配权重，聚合有用信息；因果约束阻止它在预测答案时偷看更后的答案。逐位置前馈层进一步变换表示，残差和归一化帮助堆叠网络训练。

为了理解 shape，一个普通等宽多头注意力可写为 `[B,L,H] → Q/K/V:[B,h,L,H/h] → 注意力:[B,h,L,L] → [B,L,H]`。**这只是概念解释，不是对当前外部 LLM 内部源码的断言**：真实模型可能使用不同数量的 Q/KV 头、不同位置编码和不同前馈结构。确切形状需读取用户实际 checkpoint 的 config 与对应 Transformers 模型类；本仓库没有这些具体层的实现可以逐行展开。

主线虽然使用 `DataCollatorForSeq2Seq`，也不代表模型变成了 encoder-decoder。模型构造明确使用 `AutoModelForCausalLM`，prompt 和答案拼在同一条 token 序列里。

## 6. 仓库自己实现的 Transformer：SASRec

源码：[minionerec/models/sasrec.py](../minionerec/models/sasrec.py) 的 `SASRec.forward/forward_eval`，以及 [minionerec/models/sasrec_modules.py](../minionerec/models/sasrec_modules.py)。这是可逐步确认的本地实现，作为独立基线／可选奖励模型使用。

设商品数 N、固定历史宽度 S=10、隐藏维度 hₛ（默认 32）、注意力头数 a（默认 1）：

| 操作 | shape |
| --- | --- |
| `states`；`len_states` | `[B,S]`；`[B]` |
| 商品 Embedding，表含一个 padding 行 | 表 `[N+1,hₛ]` → `[B,S,hₛ]` |
| 位置 Embedding | `[S,hₛ]`，广播加到商品向量 |
| Dropout、padding mask、LayerNorm | `[B,S,hₛ]` |
| Q、K、V 三个 Linear | 各 `[B,S,hₛ]` |
| 按隐藏维切头，再沿 batch 拼接 | 各 `[aB,S,hₛ/a]` |
| QKᵀ、key mask、下三角 mask、softmax | `[aB,S,S]` |
| 注意力乘 V、合头、加残差 | `[B,S,hₛ]` |
| 逐位置前馈网络和归一化 | `[B,S,hₛ]` |
| 按 `len_states-1` gather 最后有效位置 | `[B,1,hₛ]` |
| `s_fc` | `[B,1,N]`，随后 `.squeeze()` |

这里的缩放因子源码是 `sqrt(hidden_size)`，不是常见公式的 `sqrt(head_dim)`；默认单头两者相同，多头时不同。前馈层用 kernel size=1 的 Conv1d 做逐位置变换，转置 `[B,S,hₛ] ↔ [B,hₛ,S]`，不改变序列长度。

正常 B>1 且 N>1 时最后输出 `[B,N]`，表示每个商品一个分数。B=1 时无参数 `.squeeze()` 会把 batch 维一起去掉，不能无条件写成始终 `[B,N]`。

为什么取最后有效位置？因果注意力下，它已经能聚合全部已有历史，用这个状态预测下一个商品。SASRec 输出商品分数，主 LLM 输出 token 分数；两种模型解决相关任务，但输出空间不同。

## 7. 其他 SID 方法改变什么

- `rq/rqkmeans_faiss.py`：直接对文本向量训练 FAISS ResidualQuantizer，默认 3 层、每层 256，输出 `[N,M]` 代码；可选额外平衡分配。没有 RQVAE 的 MLP encoder/decoder。
- `rq/rqkmeans_constrained.py`：每层在残差上做有簇大小约束的 KMeans，代码原始形状为 `[M,N]`，保存时转成 `[N,M]`。发生完整代码碰撞时追加一个组内序号，最终 token 数可能变化。Python 默认 4 层，而配套 Shell 明确传 3 层。
- `rq/rqkmeans_plus.py`：把 encoder 包成 `x + MLP(x)`，要求 `e_dim == in_dim`；MLP 末层零初始化，使初始映射为恒等映射。加载 constrained 码本，再用 RQVAE Trainer 优化。

这些是替代的 SID 构建路线，不是默认 LLM forward 里连续经过的四个模块。
