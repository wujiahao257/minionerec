# 08 按训练发生的时间顺序读源码

[返回文档目录](README.md)

这篇按一次完整实验从开始到结束的时间顺序列文件。与 [07 源码阅读顺序](07_源码阅读顺序.md) 的入门路线不同，这里不先跳到 SFT，而是从原始数据一直走到评测。

**先记住主线：**

```text
原始数据
→ amazon18_data_process.py
→ amazon_text2emb.py
→ rqvae.py → rq/vae/trainer.py → RQVAE → ResidualVectorQuantizer → VectorQuantizer
→ generate_indices.py
→ minionerec/preprocessing/convert_dataset.py
→ minionerec/training/sft.py → minionerec/datasets/recommendation.py → Transformers Trainer → 外部 CausalLM
→ minionerec/training/rl.py → minionerec/datasets/recommendation.py → ReReTrainer → 外部 CausalLM
→ minionerec/evaluation/evaluate.py → EvalSidDataset → ConstrainedLogitsProcessor → minionerec/evaluation/metrics.py
```

这里选择 RQ-VAE 作为 SID 构建路线；另外三种 SID 算法是替代路线，不是都要依次训练。RL 也是可选阶段。

## 第 1 步：清洗原始数据，决定训练样本从哪来

**先读：** [minionerec/preprocessing/amazon18.py](../minionerec/preprocessing/amazon18.py)。

按实际入口依次找：

1. `parse_args` 与底部 `if __name__ == '__main__'`：确定原始评论、元数据、时间范围和输出路径。
2. `load_reviews_json2csv_style`：读取用户对商品的评论行为。
3. `process_dataset_recursive` → `load_metadata_json2csv_style` → `k_core_filtering_json2csv_style`：清洗标题、时间过滤、反复过滤低频用户和商品。
4. `convert_inters2dict_amazon18_style`：为用户、商品重新编号，并按用户时间排序。
5. `generate_interaction_list_json2csv_style`：历史最多 10 条，下一条行为作为目标。
6. `convert_to_atomic_files_json2csv_style`：按全体样本目标时间划分 80%／10%／10%。
7. `create_item_features_amazon18_style`、`load_review_data_amazon18_style` 和文件写出部分。

**输入：** 原始 reviews、metadata。

**输出：** `.train.inter`、`.valid.inter`、`.test.inter`、`.item.json`、`.inter.json`、`.review.json`、用户和商品编号映射。

**此时还没训练模型。** 读完应能解释：一位用户有 A、B、C 三次行为，为什么会形成 `[A]→B` 和 `[A,B]→C` 两条样本。

如果用 Amazon23，改读 [minionerec/preprocessing/amazon23.py](../minionerec/preprocessing/amazon23.py)，按 `main` 的调用顺序走；不用把 Amazon18 再执行一遍。

## 第 2 步：把商品标题、描述编码成连续向量

**读：** [rq/text2emb/amazon_text2emb.py](../rq/text2emb/amazon_text2emb.py)。

顺序：底部入口 → `preprocess_text` → `load_data` → `generate_text` → `load_qwen_model` → `generate_item_embedding`。遇到文本清洗，再看 [rq/text2emb/utils.py](../rq/text2emb/utils.py) 的 `clean_text`。

重点跟踪：

```text
标题 + 描述
→ tokenizer：[B,T]
→ AutoModel.last_hidden_state：[B,T,D]
→ mask 平均池化：[B,D]
→ 按商品编号排序保存：[N,D]
```

**输入：** 上一步 `.item.json`，以及用户提供的文本模型 checkpoint。

**输出：** `.emb-qwen-td.npy`。

**这一步是固定模型推理，不是微调。** 代码使用 `eval()` 和 `no_grad()`，没有 optimizer 更新。

## 第 3 步：训练 RQ-VAE，学习商品离散代码

**先读入口：** [rq/vae/rqvae.py](../rq/vae/rqvae.py) 的 `parse_args` 和底部主程序。

接着按构造和实际 forward 顺序读：

| 顺序 | 文件、类／函数 | 关注的问题 |
| --- | --- | --- |
| 1 | [rq/vae/datasets.py](../rq/vae/datasets.py)：`EmbDataset.__init__/__getitem__` | `.npy` 的一行如何变成 `[D]` 浮点 Tensor？ |
| 2 | [rq/vae/rqvae.py](../rq/vae/rqvae.py)：`DataLoader(...)` | B 个商品怎样组成 `[B,D]`？ |
| 3 | [rq/vae/trainer.py](../rq/vae/trainer.py)：`Trainer.__init__/fit/_train_epoch` | epoch、optimizer 和 batch 循环在哪里？ |
| 4 | [rq/vae/models/rqvae.py](../rq/vae/models/rqvae.py)：`RQVAE.forward` | encoder → rq → decoder 三段如何连接？ |
| 5 | [rq/vae/models/layers.py](../rq/vae/models/layers.py)：`MLPLayers.forward` | `[B,D]` 如何映射到 `[B,d]`？ |
| 6 | [rq/vae/models/rq.py](../rq/vae/models/rq.py)：`ResidualVectorQuantizer.forward` | 每层 residual 如何减去已选码本向量？ |
| 7 | [rq/vae/models/vq.py](../rq/vae/models/vq.py)：`VectorQuantizer.forward` | `[B,K]` 距离、整数索引、Embedding 查表、detach |
| 8 | 回到 `RQVAE.compute_loss` | 重建 loss 和量化 loss 如何组合？ |
| 9 | 回到 `Trainer._train_epoch` | `backward → clip_grad_norm → optimizer.step → scheduler.step` |
| 10 | `Trainer._valid_epoch/_save_checkpoint` | 如何计算碰撞率、保存模型？ |

**输入：** 商品连续向量。

**输出：** RQ-VAE checkpoint，包含 encoder、码本、decoder 权重及训练参数等。

**这才是该路线中的第一次训练。** 它学习商品编码，不学习用户下一次行为。详细 shape 看 [03](03_模型架构.md)，loss 看 [04](04_训练流程.md)。

如果选择替代路线：FAISS 读 `rq/kmeans/rqkmeans_faiss.py`；约束聚类读 `rq/kmeans/rqkmeans_constrained.py`；plus 则先准备约束聚类码本，再读 `rq/kmeans/rqkmeans_plus.py`，导出改用 `rq/kmeans/generate_indices_plus.py`。

## 第 4 步：用训练好的量化模型导出 SID

**读：** [rq/vae/generate_indices.py](../rq/vae/generate_indices.py)。

这个脚本由 `main` 组织导出流程。按以下顺序读：

```text
加载 checkpoint 和训练参数
→ EmbDataset 与不打乱的 DataLoader
→ RQVAE.get_indices
→ encoder → residual quantizer
→ 整数索引格式化为 <a_...><b_...><c_...>
→ 检查冲突并最多重分配 20 轮
→ 写商品编号到 SID token 列表的 JSON
```

**输入：** 上一步的 checkpoint 与商品向量。

**输出：** `.index.json`。

**这一步不训练推荐 LLM。** 也不需要经过 RQVAE decoder；提取离散代码就够了。运行时需通过 `--ckpt_path` 传入实际 checkpoint。

## 第 5 步：把 SID 关联回用户行为

**读：** [minionerec/preprocessing/convert_dataset.py](../minionerec/preprocessing/convert_dataset.py)。

顺序：`main` → `load_dataset` → `create_item_info_file` → `convert_interactions_to_csv`，其中 `semantic_tokens_to_id` 负责拼接各层 token。

**输入：** 第 1 步的交互文件和商品元数据，第 4 步的 `.index.json`。

**输出：** 主训练使用的 train／valid／test CSV，以及 `SID、标题、商品ID` 三列 info 文件。

**这一步只转换数据。** 看清 `history_item_sid` 与 `item_sid`，它们马上分别变成 LLM 的已知条件和监督答案。

## 第 6 步：SFT，训练模型生成正确推荐答案

**先读：** [scripts/sft.sh](../scripts/sft.sh)，只确认它调用哪个 Python 文件和传什么参数。

**再读：** [minionerec/training/sft.py](../minionerec/training/sft.py) 的 `train`，在实际构造 Dataset 的地方跳进 [minionerec/datasets/recommendation.py](../minionerec/datasets/recommendation.py)。

顺序如下：

```text
minionerec/training/sft.py::train
  1. 加载 AutoModelForCausalLM 与 tokenizer
  2. TokenExtender.get_new_tokens → add_tokens → resize_token_embeddings
  3. 构造 SidSFTDataset
       CSVBaseDataset → BaseDataset.get_inputs → SidSFTDataset.pre
       → get_history → generate_prompt → Tokenizer.encode
  4. 构造 SidItemFeatDataset、FusionSeqRecDataset
  5. ConcatDataset → HF Dataset → shuffle
  6. Trainer + DataCollatorForSeq2Seq
  7. trainer.train()
       库内部 DataLoader → 补齐 batch → model(**inputs)
       → 模型内部 causal LM loss → 反传与参数更新
  8. 保存模型和 tokenizer 到 final_checkpoint
```

**阅读重点：** `labels = [-100] * input_prompt_len + 答案token`。要能解释为什么 label 和 input_ids 同长、为什么计算 next-token loss 时需要移位、为什么标题辅助任务也能用同一个模型训练。

**输入：** CSV、商品元数据、SID 索引、基础语言模型。

**输出：** SFT 模型和扩充 tokenizer。

**从此模型已经可以推荐。** 可以直接跳到第 8 步评测，无需强制经过 RL。

## 第 7 步：可选 RL，按推荐奖励继续优化

**先读：** [scripts/rl.sh](../scripts/rl.sh) → [minionerec/training/rl.py](../minionerec/training/rl.py) 的 `train`。

顺序：

1. `minionerec/datasets/recommendation.py::SidDataset`、`RLTitle2SidDataset`、`RLSeqTitle2SidDataset`：构造 prompt 与正确答案映射。
2. `minionerec/training/rl.py` 内 `rule_reward`、`ndcg_rule_reward`：弄清每个候选为什么得到这个 reward。
3. `GRPOConfig` 和 `ReReTrainer(...)`：确认传给训练器的实际配置。
4. [minionerec/training/trainer.py](../minionerec/training/trainer.py) 的 `ReReTrainer.__init__`：模型、参考模型、生成配置、前缀表。
5. `RepeatRandomSampler`：每个 prompt 重复 G 次。
6. `_prepare_inputs`：tokenize → 生成候选 → EOS mask → 参考概率 → reward → 组内 advantage。
7. `_get_per_token_logps`：观察实际调用外部模型 forward 的位置。
8. `compute_loss`：policy 概率、KL、advantage 如何成为可导 loss。
9. Trainer 更新参数、记录日志、保存 final_checkpoint。

**输入：** SFT checkpoint、RL 样本与商品目录。

**输出：** RL checkpoint 和 tokenizer。

这里的训练样本不是提前写好的 token labels。模型先生成，reward 再判断相对好坏，loss 用这些生成 token 的概率更新参数。完整公式见 [04](04_训练流程.md)。

## 第 8 步：训练之后生成候选，算离线指标

**读：** [scripts/evaluate.sh](../scripts/evaluate.sh) 的调度顺序，然后依次打开：

1. [minionerec/evaluation/split.py](../minionerec/evaluation/split.py)：`split`，测试 CSV 分片。
2. [minionerec/evaluation/evaluate.py](../minionerec/evaluation/evaluate.py)：`main`，加载 checkpoint 与目录，建立 SID 前缀表。
3. [minionerec/datasets/recommendation.py](../minionerec/datasets/recommendation.py)：`EvalSidDataset.pre(test=True)`，只给 prompt，不给答案 token。
4. `minionerec/evaluation/evaluate.py` 的嵌套 `evaluate`：手动补齐 batch、配置 beam、调用 `model.generate`。
5. [minionerec/evaluation/logits_processor.py](../minionerec/evaluation/logits_processor.py)：`ConstrainedLogitsProcessor.__call__`，逐 token 屏蔽非法路径。
6. 回到 `minionerec/evaluation/evaluate.py`：decode、分组、写候选 SID JSON。
7. [minionerec/evaluation/merge.py](../minionerec/evaluation/merge.py)：`merge`，合并分片结果。
8. [minionerec/evaluation/metrics.py](../minionerec/evaluation/metrics.py)：`gao`，真实 SID 的排名 → HR@K／NDCG@K。

**输入：** SFT 或 RL checkpoint、测试 CSV、info 目录。

**输出：** 推荐候选 SID 列表和离线指标。这一步不更新模型参数，也没有实现在线展示、库存过滤或碰撞 SID 的唯一商品消歧。

## 仓库已经准备好的数据能省掉哪些步骤

当前 `data/Amazon/` 已附两套商品元数据、向量、SID、CSV 和 info。因此实际阅读时，如果只关心推荐训练，可从**第 6 步**开始，按需回查第 1～5 步；如果要理解整个实验如何从零构建，就按本篇 1～8 步走。

这些脚本不是一个自动连续执行的总程序。每一步通过输出文件交给下一步，且部分 Shell 使用占位路径或依赖工作目录。时间顺序告诉你“先产生什么、后消费什么”，不表示所有示例脚本都无需配置就能一键运行。
