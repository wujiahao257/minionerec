# 01 目录结构与文件职责

[返回目录](README.md) · [下一篇：数据处理](02_数据处理.md)

## 1. 目录地图

```text
MiniOneRec/
├─ data.py                         主线 SFT、RL、评测 Dataset
├─ sft.py / sft.sh                  监督微调
├─ rl.py / rl.sh                    推荐强化学习入口
├─ minionerec_trainer.py            自定义 RL Trainer
├─ evaluate.py / evaluate.sh        离线候选生成与分片调度
├─ LogitProcessor.py               SID 前缀约束
├─ split.py / merge.py / calc.py    分片、合并、计算指标
├─ convert_dataset*.py / .sh        原子交互文件转换 CSV
├─ sft_gpr.py / rl_gpr.py           GPR 实验分支
├─ ts_rec_sft.py / ts_rec_data.py   TS-Rec 实验分支
├─ ts_rec_sft.sh / ts_rec_data/     启动样例、token 语义数据
├─ sasrec.py / SASRecModules_ori.py 传统序列推荐模型
├─ utility.py                      基线辅助函数与遗留模块
├─ data/
│  ├─ amazon18_data_process*.py / .sh
│  ├─ amazon23_data_process.py / .sh
│  ├─ process.py                   较早的标题数据处理入口
│  └─ Amazon/{train,valid,test,info,index}/
├─ rq/
│  ├─ text2emb/                    商品文本转向量
│  ├─ rqvae.py / trainer.py / datasets.py / utils.py
│  ├─ rqkmeans_faiss.py / rqkmeans_constrained.py / rqkmeans_plus.py
│  ├─ generate_indices.py / generate_indices_plus.py
│  └─ models/{rqvae,rq,vq,layers,generate_indices}.py
├─ config/zero2_opt.yaml            Accelerate / DeepSpeed 配置
├─ data_test.py / tests/            数据与 API 辅助函数测试
├─ README.md / requirements.txt / LICENSE
├─ assets/                         README 图示和机构图片
└─ docs/                           本套文档
```

实际配置目录是 `config/`，不是根 README 表格中的 `configs/`。`data.py` 是数据集代码文件，`data/` 是处理脚本与数据目录；同理，`ts_rec_data.py` 与 `ts_rec_data/` 含义不同。

## 2. 主推荐与评测文件

| 文件 | 关键符号 | 在整体流程中的作用 |
| --- | --- | --- |
| [sft.py](../sft.py) | `TokenExtender`、`train` | 加载 LLM、扩充 SID 词表、混合数据集、交给 HF Trainer 训练和保存 |
| [data.py](../data.py) | `BaseDataset`、`CSVBaseDataset`、`JSONBaseDataset` | 统一读取与预编码；具体类构建不同任务 |
| [rl.py](../rl.py) | `train` 内的 reward 函数 | 混合 RL 数据、建立答案映射、配置并启动 ReReTrainer |
| [minionerec_trainer.py](../minionerec_trainer.py) | `RepeatRandomSampler`、`ReReTrainer` | 候选生成、参考模型概率、组内优势、RL loss |
| [LogitProcessor.py](../LogitProcessor.py) | `ConstrainedLogitsProcessor.__call__` | 每步只允许能继续拼成目录 SID 的 token |
| [evaluate.py](../evaluate.py) | `main`、嵌套 `evaluate` | 构建前缀表、批量生成并写预测 JSON；不在此计算最终 HR/NDCG |
| [split.py](../split.py) | `split` | 按行把测试 CSV 分成多个设备编号文件 |
| [merge.py](../merge.py) | `merge` | 按给定设备顺序合并 JSON 列表 |
| [calc.py](../calc.py) | `gao` | 比较预测 SID 和目标 SID，打印 HR/NDCG 与无效结果计数 |

三个 `.sh` 是各自 Python 入口的调用样例，不是自动可用的配置系统。`sft.sh`、`rl.sh`、`evaluate.sh` 都有模型或输出路径占位符；不能仅照抄根 README 的命令就认为已配置好。

## 3. 数据预处理文件

| 文件 | 职责与重要区别 |
| --- | --- |
| [data/amazon18_data_process.py](../data/amazon18_data_process.py) | 清洗 Amazon18、K-core、连续编号、历史窗口、时间划分；产出 `.inter`、元数据与映射 |
| [data/amazon18_data_process.sh](../data/amazon18_data_process.sh) | 相对当前工作目录调用上述脚本的固定参数样例 |
| [data/amazon23_data_process.py](../data/amazon23_data_process.py) | 用 `parent_asin` 关联商品，把毫秒时间转秒，再产出兼容格式 |
| [data/amazon23_data_process.sh](../data/amazon23_data_process.sh) | 含 `{domain}` 占位符的 Amazon23 样例 |
| [data/process.py](../data/process.py) | `gao` 直接产出标题交互 CSV 和两列 info；没有 SID，格式不能直接代替主线 SID 数据 |
| [convert_dataset.py](../convert_dataset.py) | `.inter` + `.item.json` + `.index.json` → 七列 CSV 和三列 info |
| [convert_dataset.sh](../convert_dataset.sh) | 转换脚本示例，默认路径在 `data/Amazon18`；主训练示例则读 `data/Amazon` |
| [convert_dataset_gpr.py](../convert_dataset_gpr.py) | 额外接收上下文 token，写 `e_token` 和 `user_id_original_str` |
| [data/amazon18_data_process_gpr.py](../data/amazon18_data_process_gpr.py) | 模拟上下文、商品类型和价值，生成用户评分分组特征；详见 06 |

`data/Amazon` 的 `train/valid/test` 保存两类商品的交互 CSV；`info` 保存 SID、标题、商品编号；`index` 同时存商品元数据、SID 映射和 NumPy 向量。向量不是训练好的 LLM 权重。

## 4. SID 构建文件

| 文件 | 关键入口及作用 |
| --- | --- |
| [rq/text2emb/amazon_text2emb.py](../rq/text2emb/amazon_text2emb.py) | `generate_text`、`generate_item_embedding`：标题描述、模型表示、mask 平均池化、多进程汇总 |
| [rq/text2emb/amazon_text2emb_gpr.py](../rq/text2emb/amazon_text2emb_gpr.py) | 基于上述代码补充空字符串处理，没有增加图片或广告编码器 |
| [rq/text2emb/utils.py](../rq/text2emb/utils.py) | 文本清洗、JSON、外部文本 API 调用封装、偏好 prompt 常量；API 调用不在默认向量生成链中 |
| [rq/datasets.py](../rq/datasets.py) | `EmbDataset`：加载 `.npy`，清理 NaN/Inf，返回浮点向量 |
| [rq/rqvae.py](../rq/rqvae.py) | 参数解析、构建 RQVAE 与 DataLoader、调用 `Trainer.fit` |
| [rq/trainer.py](../rq/trainer.py) | RQ-VAE 的独立优化循环、碰撞率验证、checkpoint 管理 |
| [rq/models/rqvae.py](../rq/models/rqvae.py) | `RQVAE`：MLP 编码、残差量化、MLP 重建、总 loss |
| [rq/models/rq.py](../rq/models/rq.py) | `ResidualVectorQuantizer`：循环量化剩余残差 |
| [rq/models/vq.py](../rq/models/vq.py) | `VectorQuantizer`：距离、码本选择、量化 loss、直通梯度 |
| [rq/models/layers.py](../rq/models/layers.py) | `MLPLayers`、`kmeans`、`sinkhorn_algorithm` |
| [rq/generate_indices.py](../rq/generate_indices.py) | 从 checkpoint 导出 SID，对冲突组最多重分配 20 轮；含硬编码路径 |
| [rq/models/generate_indices.py](../rq/models/generate_indices.py) | 另一份相近导出脚本，checkpoint 路径为空，且目录下导入路径需注意；不是主模型层 |
| [rq/rqkmeans_faiss.py](../rq/rqkmeans_faiss.py) | FAISS 残差量化，可选 Sinkhorn 平衡映射，直接写 SID |
| [rq/rqkmeans_constrained.py](../rq/rqkmeans_constrained.py) | 每层限制聚类大小，保存码本，并给冲突代码追加序号 |
| [rq/rqkmeans_plus.py](../rq/rqkmeans_plus.py) | 在 RQVAE 上使用残差编码器和预训练聚类码本，再训练 |
| [rq/generate_indices_plus.py](../rq/generate_indices_plus.py) | 加载 plus 结构、导出码并追加冲突序号 |
| [rq/utils.py](../rq/utils.py) | 创建目录、日志颜色、时间和 checkpoint 文件清理 |

相关启动样例分别是 `rq/rqvae.sh`、`rq/rqkmeans_constrained.sh`、`rq/rqkmeans_plus.sh`、`rq/generate_indices_plus.sh`、`rq/text2emb/amazon_text2emb.sh`。不少脚本按所在目录组织相对路径，运行时的工作目录影响路径解析；没有自动定位所有资源的逻辑。

## 5. 扩展、基线与测试

| 文件 | 作用与当前边界 |
| --- | --- |
| [sft_gpr.py](../sft_gpr.py) | 定义 `VAFT_Trainer` 价值加权 loss，但当前入口用普通 `SidSFTDataset`，没有产生该权重字段 |
| [rl_gpr.py](../rl_gpr.py) | 加入 `hepo_reward`；其方括号 SID 解析与仓库尖括号格式不匹配 |
| [ts_rec_sft.py](../ts_rec_sft.py) | `initialize_sid_token_with_text` 语义初始化，额外加入 token／描述对齐数据 |
| [ts_rec_data.py](../ts_rec_data.py) | 独立 Dataset 实现；新增 `SidTokenFeatDataset` |
| [ts_rec_sft.sh](../ts_rec_sft.sh) | 当前实际调用 `sft.py` 却传 `description_path`，与相应 Python 签名不匹配 |
| [ts_rec_data/Industrial_and_Scientific.description_keywords.json](../ts_rec_data/Industrial_and_Scientific.description_keywords.json) | 560 条 token、描述、关键词记录；当前 TS Shell 的路径不是这里 |
| [sasrec.py](../sasrec.py) | `SASRec`、`GRU`、`Caser`、`RecDataset`、独立训练评测；可向 RL 提供分数 |
| [SASRecModules_ori.py](../SASRecModules_ori.py) | 基线的多头注意力与逐位置前馈网络 |
| [utility.py](../utility.py) | 历史 padding、命中率等辅助函数；还留有未接入主线的 `NeuProcessEncoder`、`MemoryUnit` 等 |
| [data_test.py](../data_test.py) | MockTokenizer 的 Dataset 初始化测试，不等同于真实 tokenizer、模型或推荐指标测试 |
| [tests/test_minimax_provider.py](../tests/test_minimax_provider.py) | API 分发、请求、重试、文本处理测试；有需 API key 的集成测试和生成配置静态检查 |
| [tests/__init__.py](../tests/__init__.py) | 测试包标记 |
| [config/zero2_opt.yaml](../config/zero2_opt.yaml) | RL Shell 使用的 DeepSpeed ZeRO stage 2、bf16 配置 |
| [requirements.txt](../requirements.txt) | 依赖列表；包括 Torch 2.6.0、Transformers 4.57.1、TRL 0.24.0；列表存在不等于所有可选分支已验证可运行 |
| [README.md](../README.md)、[LICENSE](../LICENSE) | 项目介绍、示例与 Apache 2.0 许可；实现细节仍以源码为准 |
| `assets/` | logo、框架图、结果图、机构图片，不被训练 forward 使用 |

不要把“文件存在”理解成“默认入口使用”。识别执行路径最可靠的方式是从 `.sh` 的 Python 文件名进入，再追踪实际构造的 Dataset、Trainer 和函数调用。
