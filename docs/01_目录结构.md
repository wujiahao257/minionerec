# 01 目录结构与文件职责

[返回目录](README.md) · [下一篇：数据处理](02_数据处理.md)

## 1. 目录地图

```text
MiniOneRec/
├─ minionerec/                     推荐系统 Python 包
│  ├─ datasets/recommendation.py    主线 SFT、RL、评测 Dataset
│  ├─ training/{sft,rl,trainer}.py  主线训练入口与 RL Trainer
│  ├─ evaluation/                  推理、约束解码、分片、合并、指标
│  ├─ preprocessing/               Amazon18/23 清洗、转换、旧标题入口
│  └─ experiments/{gpr,ts}/        GPR 与 TS-Rec 实验分支
├─ scripts/                        推荐训练、评测、清洗的 Shell 样例
├─ rq/                             保留独立的 SID 构建子项目
│  ├─ text2emb/                    商品文本转向量与外部文本服务
│  ├─ models/                      RQ-VAE、残差量化、码本与 MLP
│  └─ *.py / *.sh                  量化训练、导出与启动样例
├─ data/Amazon/                    train、valid、test、info、index 数据
├─ ts_rec_data/                    SID token 的语义描述数据
├─ config/zero2_opt.yaml           Accelerate / DeepSpeed 配置
├─ tests/                         数据、API 辅助函数与目录结构测试
├─ docs/                          中文源码讲解与迁移说明
├─ assets/                        README 图片
└─ README.md / requirements.txt / LICENSE
```

主线代码统一放在 `minionerec/`，`data/` 只存数据；`rq/` 保留原有独立子项目结构。运行命令和旧路径对照见 [09 目录迁移与遗留代码检查](09_目录迁移与遗留代码检查.md)。

## 2. 主推荐与评测文件

| 文件 | 关键符号 | 在整体流程中的作用 |
| --- | --- | --- |
| [minionerec/training/sft.py](../minionerec/training/sft.py) | `TokenExtender`、`train` | 加载 LLM、扩充 SID 词表、混合数据集、交给 HF Trainer 训练和保存 |
| [minionerec/datasets/recommendation.py](../minionerec/datasets/recommendation.py) | `BaseDataset`、`CSVBaseDataset`、`JSONBaseDataset` | 统一读取与预编码；具体类构建不同任务 |
| [minionerec/training/rl.py](../minionerec/training/rl.py) | `train` 内的 reward 函数 | 混合 RL 数据、建立答案映射、配置并启动 ReReTrainer |
| [minionerec/training/trainer.py](../minionerec/training/trainer.py) | `RepeatRandomSampler`、`ReReTrainer` | 候选生成、参考模型概率、组内优势、RL loss |
| [minionerec/evaluation/logits_processor.py](../minionerec/evaluation/logits_processor.py) | `ConstrainedLogitsProcessor.__call__` | 每步只允许能继续拼成目录 SID 的 token |
| [minionerec/evaluation/evaluate.py](../minionerec/evaluation/evaluate.py) | `main`、嵌套 `evaluate` | 构建前缀表、批量生成并写预测 JSON；不在此计算最终 HR/NDCG |
| [minionerec/evaluation/split.py](../minionerec/evaluation/split.py) | `split` | 按行把测试 CSV 分成多个设备编号文件 |
| [minionerec/evaluation/merge.py](../minionerec/evaluation/merge.py) | `merge` | 按给定设备顺序合并 JSON 列表 |
| [minionerec/evaluation/metrics.py](../minionerec/evaluation/metrics.py) | `gao` | 比较预测 SID 和目标 SID，打印 HR/NDCG 与无效结果计数 |

三个 `.sh` 是各自 Python 入口的调用样例，不是自动可用的配置系统。`scripts/sft.sh`、`scripts/rl.sh`、`scripts/evaluate.sh` 都有模型或输出路径占位符；不能仅照抄根 README 的命令就认为已配置好。

## 3. 数据预处理文件

| 文件 | 职责与重要区别 |
| --- | --- |
| [minionerec/preprocessing/amazon18.py](../minionerec/preprocessing/amazon18.py) | 清洗 Amazon18、K-core、连续编号、历史窗口、时间划分；产出 `.inter`、元数据与映射 |
| [scripts/amazon18_data_process.sh](../scripts/amazon18_data_process.sh) | 自动定位项目根目录，使用 Python 模块入口的参数样例 |
| [minionerec/preprocessing/amazon23.py](../minionerec/preprocessing/amazon23.py) | 用 `parent_asin` 关联商品，把毫秒时间转秒，再产出兼容格式 |
| [scripts/amazon23_data_process.sh](../scripts/amazon23_data_process.sh) | 含 `{domain}` 占位符的 Amazon23 样例 |
| [minionerec/preprocessing/legacy_process.py](../minionerec/preprocessing/legacy_process.py) | `gao` 直接产出标题交互 CSV 和两列 info；没有 SID，格式不能直接代替主线 SID 数据 |
| [minionerec/preprocessing/convert_dataset.py](../minionerec/preprocessing/convert_dataset.py) | `.inter` + `.item.json` + `.index.json` → 七列 CSV 和三列 info |
| [scripts/convert_dataset.sh](../scripts/convert_dataset.sh) | 转换脚本示例，默认路径在 `data/Amazon18`；主训练示例则读 `data/Amazon` |
| [minionerec/experiments/gpr/convert_dataset.py](../minionerec/experiments/gpr/convert_dataset.py) | 额外接收上下文 token，写 `e_token` 和 `user_id_original_str` |
| [minionerec/experiments/gpr/amazon18.py](../minionerec/experiments/gpr/amazon18.py) | 模拟上下文、商品类型和价值，生成用户评分分组特征；详见 06 |

`data/Amazon` 的 `train/valid/test` 保存两类商品的交互 CSV；`info` 保存 SID、标题、商品编号；`index` 同时存商品元数据、SID 映射和 NumPy 向量。向量不是训练好的 LLM 权重。

## 4. SID 构建文件

| 文件 | 关键入口及作用 |
| --- | --- |
| [rq/text2emb/amazon_text2emb.py](../rq/text2emb/amazon_text2emb.py) | `generate_text`、`generate_item_embedding`：标题描述、模型表示、mask 平均池化、多进程汇总 |
| [rq/text2emb/amazon_text2emb_gpr.py](../rq/text2emb/amazon_text2emb_gpr.py) | 基于上述代码补充空字符串处理，没有增加图片或广告编码器 |
| [rq/text2emb/utils.py](../rq/text2emb/utils.py) | 文本清洗、JSON、外部文本 API 调用封装、偏好 prompt 常量；API 调用不在默认向量生成链中 |
| [rq/vae/datasets.py](../rq/vae/datasets.py) | `EmbDataset`：加载 `.npy`，清理 NaN/Inf，返回浮点向量 |
| [rq/vae/rqvae.py](../rq/vae/rqvae.py) | 参数解析、构建 RQVAE 与 DataLoader、调用 `Trainer.fit` |
| [rq/vae/trainer.py](../rq/vae/trainer.py) | RQ-VAE 的独立优化循环、碰撞率验证、checkpoint 管理 |
| [rq/vae/models/rqvae.py](../rq/vae/models/rqvae.py) | `RQVAE`：MLP 编码、残差量化、MLP 重建、总 loss |
| [rq/vae/models/rq.py](../rq/vae/models/rq.py) | `ResidualVectorQuantizer`：循环量化剩余残差 |
| [rq/vae/models/vq.py](../rq/vae/models/vq.py) | `VectorQuantizer`：距离、码本选择、量化 loss、直通梯度 |
| [rq/vae/models/layers.py](../rq/vae/models/layers.py) | `MLPLayers`、`kmeans`、`sinkhorn_algorithm` |
| [rq/vae/generate_indices.py](../rq/vae/generate_indices.py) | 从 checkpoint 导出 SID，对冲突组最多重分配 20 轮；从仓库根目录以模块方式运行并传入 checkpoint 路径 |
| [rq/kmeans/rqkmeans_faiss.py](../rq/kmeans/rqkmeans_faiss.py) | FAISS 残差量化，可选 Sinkhorn 平衡映射，直接写 SID |
| [rq/kmeans/rqkmeans_constrained.py](../rq/kmeans/rqkmeans_constrained.py) | 每层限制聚类大小，保存码本，并给冲突代码追加序号 |
| [rq/kmeans/rqkmeans_plus.py](../rq/kmeans/rqkmeans_plus.py) | 在 RQVAE 上使用残差编码器和预训练聚类码本，再训练 |
| [rq/kmeans/generate_indices_plus.py](../rq/kmeans/generate_indices_plus.py) | 加载 plus 结构、导出码并追加冲突序号 |
| [rq/vae/utils.py](../rq/vae/utils.py) | VAE 训练器使用的目录创建、日志颜色、时间和 checkpoint 清理工具 |
| [rq/kmeans/trainer.py](../rq/kmeans/trainer.py) | RQ-Kmeans+ 自己的训练循环和 checkpoint 管理，不导入 VAE 目录 |
| [rq/kmeans/models/rqvae.py](../rq/kmeans/models/rqvae.py) | RQ-Kmeans+ 内部独立维护的量化网络结构；与 VAE 路线同形，但不引用 VAE 目录 |
| [rq/kmeans/datasets.py](../rq/kmeans/datasets.py) 与 [utils.py](../rq/kmeans/utils.py) | RQ-Kmeans+ 自己的数据读取和训练辅助工具 |

相关启动样例统一放在 `rq/scripts/`，包括 `rqvae.sh`、`rqkmeans_constrained.sh`、`rqkmeans_plus.sh`、`generate_indices_plus.sh` 和 `amazon_text2emb.sh`。脚本会先切换到各自原本预期的工作目录，再解析样例中的相对路径。

## 5. 扩展、基线与测试

| 文件 | 作用与当前边界 |

| [minionerec/experiments/ts/sft.py](../minionerec/experiments/ts/sft.py) | `initialize_sid_token_with_text` 语义初始化，额外加入 token／描述对齐数据 |
| [minionerec/experiments/ts/datasets.py](../minionerec/experiments/ts/datasets.py) | 独立 Dataset 实现；新增 `SidTokenFeatDataset` |

| [tests/test_minimax_provider.py](../tests/test_minimax_provider.py) | API 分发、请求、重试、文本处理测试；有需 API key 的集成测试和生成配置静态检查 |
| [tests/__init__.py](../tests/__init__.py) | 测试包标记 |
| [config/zero2_opt.yaml](../config/zero2_opt.yaml) | RL Shell 使用的 DeepSpeed ZeRO stage 2、bf16 配置 |
| [requirements.txt](../requirements.txt) | 依赖列表；包括 Torch 2.6.0、Transformers 4.57.1、TRL 0.24.0；列表存在不等于所有可选分支已验证可运行 |
| [README.md](../README.md)、[LICENSE](../LICENSE) | 项目介绍、示例与 Apache 2.0 许可；实现细节仍以源码为准 |
| `assets/` | logo、框架图、结果图、机构图片，不被训练 forward 使用 |

不要把“文件存在”理解成“默认入口使用”。识别执行路径最可靠的方式是从 `.sh` 的 Python 文件名进入，再追踪实际构造的 Dataset、Trainer 和函数调用。
