# 04 从 Dataset 到 forward、loss 与参数更新

[返回目录](README.md) · [上一篇](03_模型架构.md) · [下一篇：推理流程](05_推理流程.md)

## 1. 先建立三个 loss 的边界

| 训练对象 | 正确答案从哪里来 | loss 想改善什么 |
| --- | --- | --- |
| RQ-VAE | 输入商品向量本身 | 离散码能否重建原向量、码本能否代表 latent |
| SFT 推荐 LLM | Dataset 中的目标 SID 或标题 | 给定 prompt，正确答案 token 的概率 |
| RL 推荐 LLM | 模型生成后与目标对比得到的 reward | 同一 prompt 下相对更好的候选概率，同时限制偏离参考模型 |

三种 loss 不在一次 forward 中相加。先做 SID 构建，再做 SFT，最后可选 RL；SID 文件在后两阶段作为固定数据读取。

## 2. RQ-VAE：最容易完整看到的手写训练循环

依据：[rq/rqvae.py](../rq/rqvae.py)、[rq/trainer.py](../rq/trainer.py)、[rq/models/rqvae.py](../rq/models/rqvae.py)、[rq/models/vq.py](../rq/models/vq.py)。

```text
EmbDataset.__getitem__ → 商品向量 [D]
→ DataLoader(shuffle=True) → [B,D]
→ Trainer.fit → _train_epoch
→ data.to(device)
→ optimizer.zero_grad()
→ model(data) = RQVAE.forward
→ out:[B,D], rq_loss:标量, indices:[B,M]
→ model.compute_loss(out, rq_loss, xs=data)
→ loss.backward()
→ clip_grad_norm_(..., 1.0)
→ optimizer.step()
→ scheduler.step()
```

### 每层量化 loss

对某层输入残差 r 和量化向量 q，记 `sg` 为停止梯度：

```text
codebook_loss   = mean((q - sg(r))²)
commitment_loss = mean((sg(q) - r)²)
L_layer         = codebook_loss + beta × commitment_loss
```

第一项让码本向输入靠拢；第二项约束输入靠近所选码，避免表示随意漂移。默认 `beta=0.25`。直通估计处理重建路径穿过离散选择的问题，具体见 03。

`ResidualVectorQuantizer.forward` 对 M 层 loss **求平均**，不是求和：

```text
rq_loss = mean_l(L_layer_l)
L_recon = mean((out - x)²)             # 默认 mse；也支持 l1
L_total = L_recon + quant_loss_weight × rq_loss
```

默认 `quant_loss_weight=1.0`。没有用户下一个商品标签参与量化训练。

`_valid_epoch` 重新提取代码，计算 `(商品数 - 唯一代码数) / 商品数`。这里用的是传给 `fit` 的同一个商品 DataLoader，并不是额外留出的推荐验证集。它衡量代码碰撞，不衡量 HR/NDCG。Trainer 保存 best loss、best collision 及按保留策略管理的 checkpoint。

## 3. SFT：真实调用顺序

依据：[minionerec/training/sft.py](../minionerec/training/sft.py) 的 `train`。该函数经 `fire.Fire(train)` 暴露为命令行入口。

### 3.1 初始化阶段

1. 固定种子，将类别标识翻译成提示语中的英文描述。
2. 根据 `batch_size // micro_batch_size` 计算梯度累积步数；多进程再除以 `WORLD_SIZE`。
3. 默认 `AutoModelForCausalLM.from_pretrained(..., torch_dtype=bfloat16)`；`train_from_scratch=True` 才从外部配置随机构造模型。
4. 加载 tokenizer，设置 `pad_token=eos_token`、左 padding。
5. `TokenExtender` 读取索引并新增 SID token；模型 resize 词表。
6. 按 `freeze_LLM` 决定全量训练还是冻结大部分参数。
7. 构造三个训练 Dataset 和一个 `SidSFTDataset` 验证集。
8. `ConcatDataset` 后转换为 Hugging Face `Dataset`，shuffle，再构造 Trainer。

数据集构造的实际调用：

```text
SidSFTDataset.__init__
→ CSVBaseDataset.__init__ → pd.read_csv
→ BaseDataset.get_inputs
→ 对每行 SidSFTDataset.pre
   → get_history → generate_prompt → Tokenizer.encode
→ self.inputs
```

因此 Dataset 初始化阶段已经完成 tokenization。之后 SFT 将各字段整列复制进 HF Dataset，并不是 DataLoader 每次现场读取 CSV。

### 3.2 一个 batch 的计算

```text
trainer.train()
→ [Transformers Trainer 内部建立并迭代 DataLoader]
→ DataCollatorForSeq2Seq
   → 左侧 padding，补到 8 的倍数
   → input_ids / attention_mask / labels : [B,L]
→ [Trainer 调用 causal LM：model(**inputs)]
→ logits:[B,L,V]，模型内部计算 loss
→ [Trainer / Accelerate 反向传播、梯度累积与优化器更新]
→ 定期验证、保存 checkpoint
```

方括号部分属于外部库调用，不是在 `minionerec/training/sft.py` 里显式写出的循环。`minionerec/training/sft.py` 没有自己的主模型 `forward` 或主线 `compute_loss` 覆盖。

`DataCollatorForSeq2Seq` 在这里的角色是把变长列表组成张量；使用它不意味着存在另一个 decoder 输入。模型仍是单序列 CausalLM。

### 3.3 为什么 label 不手动右移

Dataset 返回与 input_ids 同长的 label，prompt 对应位置是 -100。因果语言模型按前一位置预测后一 token 的契约进行对齐。这也能从仓库内 `minionerec/experiments/gpr/sft.py::VAFT_Trainer.compute_loss` 显式写出的移位看到：

```python
shift_logits = logits[..., :-1, :]
shift_labels = labels[..., 1:]
```

教学例子，prompt 最后一个 token 是 p，正确答案为 a、b、c、换行、EOS：

| 用哪个位置的 logits | 对齐的监督 token |
| --- | --- |
| p 位置 | a |
| a 位置 | b |
| b 位置 | c |
| c 位置 | 换行的第一个 token |
| 答案末尾位置 | EOS |

换行的实际 token 数由 tokenizer 决定，不能固定说一个商品答案恰好只有 3 个 token。teacher forcing 意味着训练预测 b 时输入中已经有真实 a；推理则只能使用自己刚生成的 a。

令有效监督集合为 `labels[t+1] != -100` 的位置，普通因果语言模型交叉熵的含义为：

```text
L_SFT = - average_valid log softmax(logits[b,t,:])[labels[b,t+1]]
```

这是 loss 的数学含义；主线准确的跨批次／分布式归一化细节委托给所加载模型和 Transformers，仓库没有重写它。概率归一化的类别是整个扩充词表 V，而不是 N 个完整商品。主 SFT 没有显式抽一个负商品，没有 BPR pairwise loss，也没有在 logits 上套推理时的 SID 约束。

### 3.4 Padding 与 EOS 为什么能共用编号

padding 的 `attention_mask=0`，label 填 -100；真实答案 EOS 则保留有效 mask 和对应 label。因此即使两者 token ID 相同，模型仍可通过 mask 与 label 区分“补齐位置”和“该学习结束的位置”。不能仅靠 `input_ids == eos_id` 判断 SFT 的有效监督位置。

### 3.5 优化参数与保存

`TrainingArguments` 明确设置 `adamw_torch`、bf16、warmup 20 步，按步验证与保存，`eval_steps=save_steps=0.05`，并开启 `load_best_model_at_end`、early stopping patience=3。0.05 是 Trainer 接受的比例配置，不能按字面解释成“每 0.05 个 batch”。

`minionerec/training/sft.py` 虽然定义了自定义 cosine scheduler 函数，传入 `optimizers` 的代码却被注释掉；不能说默认 SFT 已使用这个自定义调度器。

`scripts/sft.sh` 示例是 8 进程、每卡 micro batch 16、总 batch 参数 1024，对应累积步数 `1024 // 16 // 8 = 8`，有效 batch 约为 `16×8×8=1024` 条混合任务样本。参数不整除时会向下取整，并无严格校验保证等于用户填写的总 batch。

训练结束先 `trainer.save_model(output_dir)`，再把当前模型和扩充后的 tokenizer 一起保存到 `output_dir/final_checkpoint`。推理要加载匹配 tokenizer 的 checkpoint，否则 SID token 编号会错位。

### 3.6 freeze_LLM 的真实行为

`freeze_LLM=True` 时先冻结所有参数，再打开输入 Embedding 整张权重的梯度，用 hook 把旧词表行梯度归零。它不是创建一个独立的新 token Embedding 模块。

输出 head 是否随输入 Embedding 一起训练，取决于模型是否共享权重；仓库没有独立解冻未共享的输出 head。旧行梯度归零也不一般等于所有优化器设置下旧行绝对不变，尤其若另行启用 weight decay 或携带已有 optimizer 状态，需区分梯度与更新。当前 `scripts/sft.sh` 明确用 `freeze_LLM=False`。

## 4. RL：模型先生成，再知道这次生成好不好

入口：[minionerec/training/rl.py](../minionerec/training/rl.py) 的 `train`；实现：[minionerec/training/trainer.py](../minionerec/training/trainer.py) 的 `ReReTrainer`。它继承 `transformers.Trainer`，使用 `GRPOConfig`，并不是直接实例化导入的 `GRPOTrainer`。

### 4.1 数据与模型准备

`minionerec/training/rl.py` 创建 `SidDataset`、`RLTitle2SidDataset`、抽取 10,000 行的 `RLSeqTitle2SidDataset`，拼接并转换成 HF Dataset。验证集用 `SidDataset`。收集所有数据集的 `prompt2history` 和 `history2target`，供奖励函数查答案。

这些字典按 prompt 或历史字符串作为键；相同键遇到不同目标时会覆盖，验证映射也在之后 update 进去。它不是以每条样本独立 ID 存储的无歧义标签表。

`ReReTrainer.__init__` 加载待训练的语言模型，并构造参考模型；常规无 PEFT 路径从初始模型复制参考模型。`sync_ref_model=True` 时挂 `SyncRefModelCallback`，不能再描述成参考模型从头到尾完全固定。主入口未传 PEFT 配置，不能把它说成默认 LoRA 训练。

### 4.2 Sampler 与 DataLoader

`RepeatRandomSampler.__iter__` 打乱样本索引，再把每个索引连续重复 G=`num_generations` 次。例如 G=3：

```text
[2, 2, 2, 0, 0, 0, 1, 1, 1, ...]
```

目的：同一个 prompt 下形成一组候选，奖励可在组内比较。RL collator 直接返回样本列表；tokenization 放到 `_prepare_inputs` 中完成。

初始化检查全局 batch 能被 G 整除。beam 和动态采样代码又按**本地** `i % G == 0` 去重，因此实际使用这些路径时还要留意每卡分组是否完整；全局整除检查本身没有验证全部本地假设。提供的 `scripts/rl.sh` 每卡 64、G=16 满足本地整组。

### 4.3 `_prepare_inputs` 的真实顺序与 shape

下面设本地有 U 个不同 prompt、每个 G 个候选，B=U×G；P 为 prompt 补齐宽度，C 为 completion 补齐宽度，F 为 reward 函数数目。

| 顺序 | 操作 | 输出 |
| --- | --- | --- |
| 1 | 收集 prompt，tokenizer 左 padding，按配置截尾 | `prompt_ids/mask:[B,P]` |
| 2 | 新建 `ConstrainedLogitsProcessor` 和温度处理器 | 每次生成的约束状态 |
| 3 | 普通采样，或 beam 分支每 G 条取一个 prompt 生成 G 个结果 | 完整序列 `[B,P+C]` |
| 4 | 切出 completion，找首个 EOS | `completion_ids:[B,C]` |
| 5 | mask 保留首个 EOS 及之前位置 | `completion_mask:[B,C]` |
| 6 | 参考模型 forward，取生成 token 的 log probability | `ref_per_token_logps:[B,C]` |
| 7 | decode 字符串，逐 reward 函数评分 | `[B,F]` |
| 8 | 跨进程 gather，加权求和，再按 G 个分组 | 全局 reward 向量与组统计 |
| 9 | 计算 advantage，并切回本地 batch | `advantages:[B]` |

G 个候选的标准化：

```text
R_i = Σ_f weight_f × reward_f(i)
A_i = (R_i - mean_group(R)) / (std_group(R) + 1e-4)
```

代码调用 PyTorch `.std(dim=1)`，不应在精确复现时擅自替换成另一种标准差定义。

如果整组奖励都相同，A 全为 0。这一组没有相对偏好学习信号，但 KL 项仍可能产生梯度。`minionerec/training/rl.py` 暴露的 `mask_all_zero` 参数没有传入 Trainer 或参与计算；它不是已接通的过滤开关。

### 4.4 reward 具体怎么算

`minionerec/training/rl.py::train` 内部定义：

| 选项 | 真实计算 |
| --- | --- |
| `rule` | 去除首尾特定空白／引号后与目标完全相同为 1，否则 0 |
| `ranking_only` | 组内至少命中一次时，命中候选记 0，错误候选按排名给负值；整组无命中则全 0 |
| `ranking` | 同时使用 `rule_reward` 和 `ndcg_rule_reward`，默认 reward 权重各为 1 |
| `semantic` | 查外部 pickle 向量，计算目标与生成商品的 cosine similarity |
| `sasrec` | 加载 SASRec，取用户历史对生成商品的未归一化预测分数 |

排名惩罚的等价公式，j 为从 0 开始的候选次序：

```text
w_j = (1 / log2(j+2)) / Σ_k (1 / log2(k+2))
r_rank(j) = -w_j  （错误候选，且本组至少一个命中）
r_rank(j) = 0     （命中，或本组全错）
```

所以较靠前的错误惩罚更大。这个 reward 用候选列表位置，不是在这里重新读取模型概率做排名，也不是直接把整份 NDCG 指标当成每条 reward。

`semantic` 依赖用户提供且与 info 编号一致的向量文件；`sasrec` 同样要求编号和历史格式匹配。默认混合任务包含标题／描述文本，而原始 `cf_reward` 把历史拆成 SID 查表，因此不能认为该奖励选项无条件适用于默认所有任务。

### 4.5 `_get_per_token_logps`：一次可明确定位的 LLM forward

```python
logits = model(input_ids=..., attention_mask=...,
               logits_to_keep=C+1).logits
logits = logits[:, :-1, :]
logits = logits[:, -C:, :]
target_ids = input_ids[:, -C:]
logps = selective_log_softmax(logits, target_ids)
```

支持 `logits_to_keep` 的模型先只计算尾部所需 logits，之后对齐为 `[B,C,V]`。`target_ids:[B,C]` 选择每个位置实际生成的 token，得到 `[B,C]` 的 log probability。为什么多请求一位？最后一个输入 token 的 logits 预测序列外的下一个 token，需要去掉；保留 C+1 才能在移位后有 C 个监督位置。

函数还在输出上做尾部切片，但这不表示不接受 `logits_to_keep` 参数的模型也能自动兼容：参数在 forward 调用时已经传了进去。

### 4.6 `compute_loss`：准确按本仓库的式子读

将 prompt 和 completion 拼回 `[B,P+C]`，用当前模型算 `lᵢₜ=log πθ`，参考模型缓存为 `rᵢₜ=log πref`：

```text
deltaᵢₜ = rᵢₜ - lᵢₜ
KL_estᵢₜ = exp(deltaᵢₜ) - deltaᵢₜ - 1
ratioᵢₜ = exp(lᵢₜ - stop_gradient(lᵢₜ))
token_lossᵢₜ = -(ratioᵢₜ × Aᵢ - beta × KL_estᵢₜ)
```

默认聚合方式是先对每条 completion 的有效 token 求平均，再对 B 条求平均：

```text
L = mean_i [ Σ_t(maskᵢₜ × token_lossᵢₜ) / Σ_t maskᵢₜ ]
```

这里 `ratio` 前向数值为 1，却不代表没有梯度：右边 detach 的分支不求导，左边仍对当前 log probability 求导。正 advantage 会推动当前生成 token 的概率增加，负 advantage 则反向推动；KL 项抑制偏离参考策略。

当前没有显式保存 old-policy log probability，没有 PPO 式 ratio clipping，没有 value 网络或 critic。不要根据“GRPO”名字把这些未出现的代码写进实现。

两个选项只按实际公式理解：

- `dapo=True`：改成所有有效 token 的总和除以总 token 数，长答案占更大权重。
- `gspo=True`：先把 token log ratio 在序列内平均后取 exp，结合序列平均 KL，再按序列平均 loss。

同时打开时 `if dapo / elif gspo` 使 DAPO 分支优先。这些是本仓库实现的变体，不能据名称宣称复现了相应算法的全部机制。

### 4.7 Trainer 如何更新参数

```text
Trainer 的训练 DataLoader
→ ReReTrainer._prepare_inputs（生成、reward、advantage、参考 logps）
→ ReReTrainer.compute_loss（当前模型 forward 与 RL loss）
→ Trainer / Accelerate backward
→ 梯度累积、优化器更新、scheduler
→ prediction_step / log / checkpoint
```

`minionerec/training/rl.py` 配置 `paged_adamw_32bit`、cosine、warmup ratio 0.03、max grad norm 0.3、bf16。`scripts/rl.sh` 用 Accelerate 和 `config/zero2_opt.yaml` 的 ZeRO stage 2。最终保存模型和 tokenizer 到 `final_checkpoint`。

`scripts/rl.sh` 的 batch 64 是每卡重复后的候选行数。8 卡、G=16 时，一次全局 micro step 是 512 个候选，按完整分组理解为 32 个 prompt；累积 2 步则约 64 个 prompt 的候选贡献一次更新。不要把 RL batch 直接等同于相同数量的不同用户历史。

## 5. 训练实现里必须保留的边界

- RL `beam_search=True` 的 generation config 实际是 `do_sample=True`。离线 `minionerec/evaluation/evaluate.py` 才显式在 `generate` 调用参数中强制 `False`。
- `test_during_training=True` 路径把同一个有 `count` 状态的约束处理器先用于测试生成、再用于训练生成，中间未重置；测试 beam 宽度还可能不同。不能把该路径当作已保证等价于独立离线评测。`scripts/rl.sh` 关闭了它。
- vLLM 分支代码存在，但 `is_vllm_available`、`LLM`、`SamplingParams` 的导入被注释；不能称为当前可直接启用的完整实现。
- 部分辅助 Dataset 可返回 None，主线 `BaseDataset.get_inputs` 不统一过滤 None。默认参数通常不走相应过滤分支，但改开关时不能只看类名。
- 主线没有训练性能基准或完整端到端测试证明所有 checkpoint、依赖版本和分支组合均可用。本篇是静态调用链与公式解释，不是训练成功报告。
