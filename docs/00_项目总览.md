# 00 项目总览

[返回目录](README.md) · [下一篇：目录结构](01_目录结构.md)

## 1. 它解决什么问题

MiniOneRec 把“根据用户按时间排列的商品交互历史，预测下一个商品”转换成语言模型的生成任务。主线输入是一段包含历史商品 Semantic ID（简称 SID）的文本；主线输出是下一个商品的 SID 字符串。

例如，仓库 Industrial 训练集第一条记录的历史商品编号是 `117`，目标编号是 `118`。对应输入历史 SID 为 `<a_165><b_107><c_44>`，目标 SID 为 `<a_104><b_118><c_176>`。模型并不直接输入用户编号 `A22`，也不直接回归商品的星级评分。它学习：“在这样的历史条件下，下一个 SID 的各个 token 应该是什么？”

依据：[minionerec/datasets/recommendation.py](../minionerec/datasets/recommendation.py) 的 `SidSFTDataset.get_history/pre`、`EvalSidDataset.get_history/pre`；[minionerec/training/sft.py](../minionerec/training/sft.py) 的 `train`。

这里的交互来自 Amazon 评论记录。代码将时间上下一条交互视为监督目标，没有先按评分筛出“喜欢”的商品。因此不能把每个样本都解释成高评分购买或明确的正反馈标签。

## 2. 四个阶段，三种不同的学习目标

| 阶段 | 输入 → 输出 | 学习或计算什么 | 主要入口 |
| --- | --- | --- | --- |
| 商品文本编码 | 标题、描述 → 连续向量 | 固定文本模型的表示；此处不训练它 | `rq/text2emb/amazon_text2emb.py` |
| SID 构建 | 连续向量 → 多层离散码 | RQ-VAE 重建与量化，或残差聚类 | `rq/vae/rqvae.py` 等 |
| SFT | 历史／商品问答 → 正确答案 token | 答案位置上的自回归交叉熵 | `minionerec/training/sft.py` |
| 推荐导向 RL | prompt → 一组模型生成答案 | 奖励、组内相对优势、参考模型 KL | `minionerec/training/rl.py`、`minionerec/training/trainer.py` |

推理在训练之后单独运行 `minionerec/evaluation/evaluate.py`。RL 不是 SFT 能否推荐的前置条件；加载 SFT checkpoint 也可以生成候选。

SID 构建与推荐模型训练通过文件衔接。主线没有把 RQ-VAE 放进 LLM 的 forward，也没有用推荐 loss 端到端回传到商品文本编码器或量化器。

## 3. 完整数据流

```text
原始 Amazon metadata + reviews
  │ minionerec/preprocessing/amazon18.py（或 Amazon23 入口）
  ├─ 商品元数据 .item.json
  │    └─ title + description
  │         └─ AutoModel → masked mean pooling → .emb-qwen-td.npy
  │              └─ RQ-VAE / RQ-Kmeans / constrained / plus
  │                   └─ 商品编号 → SID token 列表：.index.json
  └─ 行为清洗、按用户排序、滑窗、全局按目标时间划分
       └─ .train.inter / .valid.inter / .test.inter

.inter + .item.json + .index.json
  └─ minionerec/preprocessing/convert_dataset.py
       ├─ train/valid/test CSV：历史 ID、历史标题、历史 SID、目标
       └─ info TXT：SID、标题、商品编号

CSV + 元数据 + SID 索引
  └─ minionerec/training/sft.py → minionerec/datasets/recommendation.py → 扩充词表后的 CausalLM → SFT checkpoint
       └─ minionerec/training/rl.py → ReReTrainer → RL checkpoint（可选）

checkpoint + test CSV + info TXT
  └─ minionerec/evaluation/evaluate.py → 约束生成 → 每条历史的候选 SID 列表
       └─ minionerec/evaluation/merge.py → minionerec/evaluation/metrics.py → HR@K、NDCG@K
```

这些是多个独立脚本组成的流程，没有一个自动串起所有阶段的总控程序。仓库已经附带两套 CSV、商品元数据、SID 和向量，可从 SFT 开始读，不必先运行量化训练。

## 4. 为什么要用 SID

商品标题长短不同，可能重复；普通整数商品编号虽然短，但编号大小本身不表达内容。项目先从商品文本得到向量，再把向量量化成多个码，例如：

```text
商品 118 → [<a_104>, <b_118>, <c_176>]
```

`a/b/c` 表示码的层次，数字表示该层码本中的编号。残差量化的后续层用于表达前面层尚未解释的向量残差。它不是人为设定的“一级商品类目 → 品牌 → SKU”；代码没有给每层规定这种语义。

SFT 把每一种 SID token 加进 tokenizer 的词表。一个商品于是通常由三个新 token 表示；多个商品可以共享其中一些 token。为什么这样写？相似内容有机会共享代码片段，而语言模型能把生成长标题的任务变成生成短代码序列的任务。不过“有相同前缀必然属于某个真实类目”并不是代码保证。

## 5. 模型到底在哪里

主推荐模型没有在本仓库定义成 `MiniOneRec(nn.Module)`。它由 `AutoModelForCausalLM.from_pretrained(base_model)` 加载；具体层数、隐藏维度、位置编码、注意力变体由用户提供的 checkpoint 决定。

仓库自己实现的模型主要是：

- `rq/vae/models/rqvae.py::RQVAE`：学习商品向量的离散表示。
- `rq/vae/models/rq.py::ResidualVectorQuantizer` 和 `vq.py::VectorQuantizer`：逐层量化。

主 LLM 的 Transformer 实现由加载的外部模型提供；传统推荐基线已从当前学习版本移除。

## 6. 默认入口实际启用了什么

`minionerec/training/sft.py::train` 拼接三个 Dataset：

| Dataset | 学习任务 |
| --- | --- |
| `SidSFTDataset` | 历史 SID → 下一个 SID |
| `SidItemFeatDataset` | 单商品 SID ↔ 商品标题 |
| `FusionSeqRecDataset` | 历史 SID → 下一个商品标题 |

最后一个类虽然有生成描述的方法，但当前 `pre` 实际固定选择标题任务；随机选择描述任务的代码放在多行字符串中，没有执行。

`minionerec/training/rl.py::train` 同样混合任务：历史 SID → SID、标题或描述 → SID、历史标题 → SID。奖励默认参数是 `rule`，而仓库 `scripts/rl.sh` 明确传入 `ranking`，使用正确性奖励加排名惩罚。训练的 beam 分支设置了 `do_sample=True`；不能把它与离线评测的确定性 beam search 混为一谈。

## 7. 这份代码没有提供什么

主线没有在线推荐 HTTP 服务、用户行为实时存储、商品库存过滤、曝光日志闭环、多阶段召回精排服务，也没有自动将所有候选 SID 消歧为唯一商品的业务层。离线评测输出的是 SID 列表。

更具体地说：

- 没有仓库内自定义的主 LLM Transformer 实现；它依赖 Transformers 和外部 checkpoint。
- 没有从评论字段到端到端多模态训练的主线；Amazon23 即使保存图片 URL，当前文本编码只选标题和描述。
- 默认主线没有先生成推理过程再推荐。偏好／推理格式 Dataset 和 TS-Rec 分支存在，但不能据此宣称完整在线思考系统已接通。
- 没有保证所有商品 SID 唯一。实测 Industrial 有 3,686 个商品、3,670 个不同 SID；Office 有 3,459 个商品、3,444 个不同 SID。

因此，应把它理解为一个可以研究 SID、语言模型微调和推荐 RL 的离线实验代码库。后文会逐步解释每一段真实计算，同时保留这些实现边界。

## 新增扩展：SIM 精排

原 MiniOneRec 主流程之外，当前新增 [SIM 模块](../minionerec/sim/README.md)，接收生成候选并根据长短期兴趣做商品级精排。它不是原仓库已有的训练阶段，也不改变原 SFT/RL 损失。
